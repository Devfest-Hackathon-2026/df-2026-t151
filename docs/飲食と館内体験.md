# 飲食・館内体験の初期実装

2026年11月9日。ユーザーBと相談して決めた計画用の方針であり、施設公表値・実測値・大会ルールではない。

## 対象と採用理由

ユーザーの追加指定により、有効な外観観察1件を先頭の必須枠とし、屋内カフェ・軽食・小規模展示などの追加案を合わせて最大3件にする。外観が成立しなければ候補なしと理由を表示し、飲食だけの提案は返さない。短い体験から始め、種類別の時間範囲と待ち時間の推定を使う。未知の待ちを0分にせず、暫定候補として表示することをユーザーが選択した。大型施設の全館鑑賞、コース料理、予約必須・固定の開始時刻がある体験は初期対象外。

GeminiはGoogle Mapsを参照して候補と利用条件を探索する。経路時間はRoutes、営業時間はPlaces、時間の加算と期限判定は通常のサーバー処理で行う。Geminiが回答した所要時間を計算値として使わない。

## 計画用の時間範囲

| 種類       | 体験     | 推定待ち | 会計・退出 | 合計の推定上限 |
| ---------- | -------- | -------- | ---------- | -------------- |
| カフェ     | 15〜25分 | 5〜15分  | 5分        | 45分           |
| 軽食       | 20〜35分 | 5〜20分  | 5分        | 60分           |
| 小規模展示 | 15〜30分 | 0〜10分  | 5分        | 45分           |

上限は時間適合を判定するための仮定で、実際の待ち・滞在が必ずこの時間以内になるという意味ではない。時間幅は `src/server/experience-profiles.ts` に集約する。期限に合わせて短縮せず、往路・復路の徒歩時間と余裕10分を別に加える。例えば徒歩10分＋カフェ45分＋徒歩10分＋余裕10分なら必要75分。

公開するexperienceDurationは体験＋会計・退出の範囲で、待ちはtime.waitSecondsへ別加算する。有効な同一地点・同一体験の登録値→公式→統計→推定の優先順位は維持する。登録・公式値を渡す側は、会計・退出など同じ体験範囲への適用を確認する。登録台帳や公式所要時間の自動取得器は未接続。

上位の根拠で待ち込みと確認できた場合、waitTreatment=included・追加waitSeconds=0とし、二重加算しない。推定の待ちを含むことはESTIMATED_WAIT・isProvisional=trueで維持する。開始見込みは待ちの推定上限の後で、受付締切もこの時刻と比較する。矛盾する時間範囲は除外する。

## 採用に必要な根拠

- 地点・目的地・体験IDが一致するHTTPS出典と利用条件。確認から15分以内で、訪問終了まで有効であること。
- 目的地の敷地・同じ包含施設の外にあること。既知のPlaces包含関係を優先し、AIの主張で上書きしない。
- 屋内利用、予約不要の当日利用、固定の開始時刻がないこと。カテゴリやdineInだけから屋内と推測しない。
- 入場料の要否、最終入場・ラストオーダー等の受付締切。日時があるなら明示タイムゾーン付き。別の締切なしとする場合も出典の明示が必要で、記載欠落は「なし」に変換しない。
- 小規模展示は、短時間の小規模な展示である根拠と対応施設カテゴリ。飲食・展示とも営業状態と訪問全体の営業時間をPlacesで照合する。

最初のMaps回答にある利用条件の文を、同じ地点のgroundingSupports・groundingChunksに照合する。抽出処理に新しい根拠を作らせず、選択された元の文を保持する。ただし出典参照はAIの意味解釈の正しさや現地での利用を保証しない。条件が取れない・矛盾する場合は除外し、候補数を埋めない。入場料が必要な展示も、予約・開始時刻・受付条件が確認できれば対象にできる。料金の金額は未取得のため、無料を推測して表示しない。

## 再計算と経過時間

到着・開始・退出を計測する新しい操作は追加しない。再計算の通信が完了した現在のサーバー時刻を基準に、送信された最新の出発地点から残り行程を計算する。既存の現在地再取得・手動指定を使い、古い検索時刻のまま期限を判定しない。

体験の開始・経過分を自動追跡しないため、未完了の選択体験は全所要時間で再評価し、過ごした分を自動減算しない。終了後は既存の「寄り道を終えて直行」を使う。選択後の再検証は同じ地点・同じ体験IDだけを再取得し、カフェから軽食などへ自動変更しない。署名の有効期限は従来の5分。

## 天候と表示

比較できる予報が揃った場合、雨・雪・風等の影響がない時間帯を優先し、影響のある候補同士は根拠のある屋内体験を優先する。その評価後に有効な外観1件を先頭の必須枠へ置き、残りの枠は追加体験を優先する。屋内同士は徒歩2区間と屋外になり得る待ち時間で比較する。待ち込み総時間でも待ちの屋外可能性を消さない。雷雨・大雨等は徒歩移動を含む屋内案も除外する。予報欠損時の分類内順位、取得数・時間上限、通信後の再評価は従来どおり。

既存のAPI形式を維持し、experienceIdにcafe-break-v1／light-meal-v1／small-exhibit-v1を追加する。推定待ちはESTIMATED_WAITとisProvisionalで示し、crowdはunknownを維持する。体験の分類・大きな体験見出し・説明・場所名・Maps出典を候補と行程に常時表示し、詳細に待ちの扱い・注意を表示する。飲食代は「価格未確認」、展示は「入場・利用料金は現地確認」。[外観と追加体験のfixture](../fixtures/search-mixed-success.json)は全て架空のテスト用で、アプリ・実APIでは読み込まない。

## 分担・検証の境界

Bはサーバー・計算・根拠確認を実装。A担当の画面には、推定を確定値と誤認しないための表示を最小限追加した。APIのJSON形式・依存は変更しない。後続のユーザー依頼でアプリの架空デモを削除し、fixturesは自動テスト用だけに残した。詳細な検証・公開結果は [検証結果.md](検証結果.md) と[Cloud Run公開記録](CloudRun公開手順.md)を参照。
