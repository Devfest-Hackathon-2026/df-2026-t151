# 候補の不明情報と除外理由

2026年11月9日のユーザー指定。従来の「利用条件・営業情報が不明なら除外」より、この方針を優先する。

## 候補と行程

- 探索範囲は出発地点から直線距離3km以内。3kmちょうどを含み、超える候補は除外する。AIへの探索指示、取得後の距離照合、Nearby代替経路の既定値と上限を揃える。
- 実在地点とMaps出典の対応は引き続き照合する。利用条件の根拠不足だけでは除外せず、屋内利用・予約・開始時刻・入場料要否・受付締切・展示規模・目的地外での利用などを不明として保持する。出典のない条件を確認済みへ変換しない。
- 営業状態が不明な場合は「営業状態は不明」、訪問時間帯の営業時間が分からなければ「営業時間は不明」とカードに明記する。`opening.status=unknown`と暫定候補のフラグを返し、営業時間を照合済みとは表示しない。
- カードでは未確認条件があることを案内する。「行程を見る」の再取得でも不明を理由に落とさず、同じ地点・体験を維持し、行程の上部に不明項目をすべて列挙する。
- `CLOSED_TEMPORARILY`・`CLOSED_PERMANENTLY`は除外する。取得した営業時間に対して訪問時間帯が営業時間外、または確認できた最終入場・ラストオーダーに間に合わない場合も除外する。未知の営業時間を営業時間外と推測しない。
- 目的地内部・予約必須・固定開始・屋内利用不可など、利用できない条件が確認できた場合の除外は維持する。経路なし・到着期限超過・雷雨等・件数上限も維持する。
- 目的地との包含関係は、候補と指定された目的地の地点IDをPlacesの関係情報で照合する。Geminiが`outsideDestination: false`を返しただけの場合は、`UNCONFIRMED_DESTINATION_RELATION`を付けて暫定候補として評価する。屋内にあることや別の建物のテナントであることは、それだけで目的地内部の根拠にしない。
- 時間見積もりは既存の推定上限・待ち・会計/退出・余裕10分を維持する。外観候補を先頭に含めるルールと最終最大3件、AI探索最大4件・経路評価最大4件は変更しない。

## ブラウザへの除外理由出力

候補検索・行程再検証の応答に任意の`exclusions`を追加する。ブラウザのAPIクライアントが`console.info`と`console.table`で出力する（画面を印刷する`window.print()`ではない）。施設名、除外段階、理由コードと説明、参照元、参照URL、判断に使った値を確認できる。

例：閉業ならGoogle PlacesのbusinessStatus、営業時間外なら取得した営業時間枠、範囲外なら計算距離と3,000mの上限、時間不足なら移動秒数・採用した体験上限・待ち・余裕・残り時間・必要時間を出す。AI出典との照合失敗や件数上限、天候による除外も区別する。

検索・行程再検証でPlacesの包含関係に基づいて除外した場合は、情報源を`Google Places`、判断値を`destinationRelationSource: google_places`として出力する。別途得た利用条件の`outsideDestination`がある場合は、その値と出典種別の`outsideDestinationSource`（`grounded_maps`または`registered`）を併記する。

AI候補のPlace Detailsが`UPSTREAM_UNAVAILABLE`で失敗した場合は、その候補だけを`DETAILS_UNAVAILABLE`として除外し、取得できた候補の検証を続ける。診断は探索段階`discovery`、提案の出典タイトル、情報源`Google Places`、`facts.retryable`だけを含め、エラー本文や生応答を返さない。応答には`AI_CANDIDATE_DETAILS_UNAVAILABLE`の警告を1件追加する。全件が再試行不可の失敗なら候補なしとして続けるが、候補が残らず再試行可能な失敗が1件でもある場合は、その再試行可能なエラーを返す。タイムアウト・利用制限・内部エラー・中断は除外へ変換しない。

座標、出発地点、認証情報、Cookie、候補トークン、要求本文・外部サービスの生応答は診断へ入れない。公開施設の名前・営業情報など、明示した判断用項目だけを返す。サーバー側のログ出力は追加せず、既存のログ設定も変更しない。

`opening.status`の語彙追加と任意の`exclusions`は共通型・API仕様・架空fixtureへ反映する。A領域の変更は不明事項の表示とブラウザの診断出力に限り、PRで共有する。

## 確認範囲

自動テストで不明情報の保持、行程までの同一体験維持、明確な閉業・営業時間外の除外、3kmの境界、コンソールに渡す診断値、カード/行程の表示を確認する。本番のHealthチェック・実検索は行わず、本番デプロイは別工程とする。
