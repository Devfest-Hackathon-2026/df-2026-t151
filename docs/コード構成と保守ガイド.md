# コード構成と保守ガイド

よりみちは、Next.jsの画面とHTTP APIを同じアプリで配信する。画面からサーバーまで処理を追うときは、対象のAPIルートから入力検証、処理本体、外部サービスとの通信の順に読む。機能を拡張する際の制約は別資料にまとめている。[拡張性と設計](拡張性と設計.md)

## フォルダ構成

| フォルダ                     | 主な責務                                                                           |
| ---------------------------- | ---------------------------------------------------------------------------------- |
| `src/app/`                   | ページ・レイアウト・共通スタイルとHTTP APIの入口                                   |
| `src/components/`            | 入力、場所検索、候補カード、行程などの画面部品                                     |
| `src/lib/api/`               | ブラウザとサーバーで共有するAPIの型                                                |
| `src/lib/client/`            | ブラウザ側のAPI呼び出し、画面状態の変換、表示用の整形                              |
| `src/server/`                | 入力検証、検索、候補評価、再検証、Googleサービスとの通信                           |
| `tests/`・`tests/helpers/`   | Node.jsの自動テストと、固定時刻・経路・利用条件などを作る補助関数                  |
| `fixtures/`                  | 自動テスト用の架空のAPI応答例                                                      |
| `public/`                    | 静的ファイルの配置先。現時点の追跡ファイルは空ディレクトリを保持する`.gitkeep`のみ |
| `docs/`                      | 企画、要件、API仕様、開発・公開手順、検証記録                                      |
| `.github/`・`.devcontainer/` | GitHub Actions・PRテンプレートと開発コンテナ設定                                   |

## リクエストの流れ

1. **場所検索**。入力フォームが`GET /api/v1/places`を呼ぶ。サーバーが検索語と利用枠を検査し、Google Places Text Searchの結果を画面用に整える。
2. **候補検索**。`POST /api/v1/recommendations`で入力を検証し、目的地の詳細と直行経路を取得する。Geminiの探索結果をGoogle Mapsの出典と照合し、Place Detailsで候補の詳細を取得する。目的地との関係、利用条件、経路、時間、天候を評価して候補を絞り、選択に使うトークンを付ける。
3. **行程再検証**。`POST /api/v1/itineraries/validate`で署名と検索条件を照合する。選択された地点・体験について、最新の詳細・経路・利用条件・天候を取り直して評価する。画面は再検証結果を行程または検索画面へ反映する。

## ページとAPIの入口（`src/app/`）

- ホームの見出し、プランナー、位置情報案内への導線を組み立てる。[page.tsx](../src/app/page.tsx)

- 画面全体の配色、フォーム、候補カード、行程、位置情報案内のスタイルを定義する。[globals.css](../src/app/globals.css)
- `/about`で位置情報の送信先、用途、Google Maps連携の保存期間を案内する。[about/page.tsx](../src/app/about/page.tsx)
- `GET /api/health`でアプリの起動状態を返す。[api/health/route.ts](../src/app/api/health/route.ts)
- `GET /api/v1/capabilities`で認証・署名の設定から利用可能な移動手段や動作モードを返す。[api/v1/capabilities/route.ts](../src/app/api/v1/capabilities/route.ts)
- `GET /api/v1/places`に場所検索ハンドラーを割り当てる。[api/v1/places/route.ts](../src/app/api/v1/places/route.ts)
- `POST /api/v1/recommendations`に候補検索の検証と処理を割り当てる。[api/v1/recommendations/route.ts](../src/app/api/v1/recommendations/route.ts)
- `POST /api/v1/itineraries/validate`に行程再検証の検証と処理を割り当てる。[api/v1/itineraries/validate/route.ts](../src/app/api/v1/itineraries/validate/route.ts)

## 共通型とブラウザ側の処理（`src/lib/`）

- 場所検索・候補検索・行程再検証・エラーの入出力を共通の型で定義する。[api/types.ts](../src/lib/api/types.ts)
- ブラウザからAPIを呼び、要求IDの照合、応答検査、エラー表示に必要な情報の変換を行う。[client/planner-api.ts](../src/lib/client/planner-api.ts)
- 検索・再検証の結果を表示用の状態に変換する。再検証に失敗した場合は、出発地点の一致などを確認して表示先を決める。[client/trip-estimates.ts](../src/lib/client/trip-estimates.ts)
- 日本時間の表示、秒から分への換算、入力欄の初期到着時刻を扱う。[client/trip-format.ts](../src/lib/client/trip-format.ts)
- 出発地・経由地・目的地からGoogleマップの徒歩ルートURLを組み立てる。[client/maps-directions.ts](../src/lib/client/maps-directions.ts)
- APIが返した除外理由と判断値をブラウザのコンソールに表示する。[client/candidate-diagnostics.ts](../src/lib/client/candidate-diagnostics.ts)

## サーバー処理（`src/server/`）

### HTTPリクエストの受付と行程

- 設定値を検査して徒歩対応と動作モードを返す。実際のGoogle API疎通は別途確認する。[api-capabilities.ts](../src/server/api-capabilities.ts)
- 場所検索のクエリと長さを検査し、利用枠を適用してHTTP応答へ変換する。[places-handler.ts](../src/server/places-handler.ts)
- 候補検索・行程再検証で、JSON本文の読み取り、プロセス全体の利用枠、エラー応答を共通化する。[planner-post-handler.ts](../src/server/planner-post-handler.ts)
- API入力の構造、座標、到着期限、対応する移動手段、選択項目を検査する。[request-validation.ts](../src/server/request-validation.ts)
- 署名付きCookieと、プロセス内の利用者別・操作別の回数を管理する。[cookie-rate-limit.ts](../src/server/cookie-rate-limit.ts)
- 候補検索や行程再検証で、複数の外部呼び出しに共通の処理期限と中断シグナルを渡す。[request-budget.ts](../src/server/request-budget.ts)
- 目的地の詳細を取得し、候補探索と天候取得を組み合わせ、候補に署名してAPI応答を組み立てる。[recommendations.ts](../src/server/recommendations.ts)
- 選択トークンを照合し、同一地点・体験の経路、利用条件、時間、天候を再評価する。[itinerary-validation.ts](../src/server/itinerary-validation.ts)
- 候補トークンを発行・検証し、選択地点・体験を目的地・到着期限・移動手段に結び付ける。[option-token.ts](../src/server/option-token.ts)

### 候補探索とGoogleサービス

- GeminiでMaps出典付きの候補を探索し、取得済みの回答から構造化データを抽出する。[grounded-detours.ts](../src/server/grounded-detours.ts)
- Geminiの探索・抽出リクエストと、候補や利用条件の出力スキーマを組み立てる。[grounded-detours/requests.ts](../src/server/grounded-detours/requests.ts)
- Geminiの候補を元のMaps出典・根拠文と照合し、利用条件と診断を組み立てる。[grounded-detours/response.ts](../src/server/grounded-detours/response.ts)
- 探索入力、抽出結果、Maps出典の内部型を定義する。[grounded-detours/types.ts](../src/server/grounded-detours/types.ts)
- Geminiの提案をPlace Detailsと照合し、3kmの直線距離、詳細取得エラー、選択済み候補の根拠更新を扱う。[grounded-candidates.ts](../src/server/grounded-candidates.ts)
- Google Places Nearby Searchと、Places応答から候補用の地点情報を組み立てる共通処理を提供する。公開の候補検索はGeminiによる探索を使う。[nearby-candidates.ts](../src/server/nearby-candidates.ts)
- Google Places Text Searchを呼び、地点・住所・座標・提供元を取り出す。[places.ts](../src/server/places.ts)
- 目的地と候補の詳細をPlace Detailsから取得する。[place-details.ts](../src/server/place-details.ts)
- Google Routesへ徒歩経路を問い合わせ、距離と秒数を返す。[routes.ts](../src/server/routes.ts)
- 固定のGoogle API宛てに、認証ヘッダー、タイムアウト、応答サイズ上限を適用して通信する。[google-http.ts](../src/server/google-http.ts)
- 外部サービスの失敗を、公開してよいコードと再試行可否にそろえる。[google-service-error.ts](../src/server/google-service-error.ts)
- Maps系APIのAPIキー方式・サービスアカウント方式を選び、認証ヘッダーを作る。[maps-auth.ts](../src/server/maps-auth.ts)
- Vertex AIのプロジェクトとロケーションを検証し、Geminiの接続先を組み立てる。[vertex-auth.ts](../src/server/vertex-auth.ts)
- ADCから短期アクセストークンを取得し、認証・課金先ヘッダーを作る。[google-adc.ts](../src/server/google-adc.ts)

### 候補選定・時間・天候

- 直行見積もり、候補探索、事前除外、経路取得、天候評価と最終選定の順序を管理する。[detour-search.ts](../src/server/detour-search.ts)
- 目的地との関係、閉業、利用条件などを先に検査し、経路計算へ進む候補を絞る。[detour-search/selection.ts](../src/server/detour-search/selection.ts)
- 出発地点から候補まで、候補から目的地までの徒歩経路を、同時実行数を制限して取得する。[detour-search/routes.ts](../src/server/detour-search/routes.ts)
- 地点・利用条件・体験プロファイルから、候補ごとの体験内容と時間の根拠を組み立てる。[detour-search/experience.ts](../src/server/detour-search/experience.ts)
- 通信後の基準時刻で直行見積もりを更新し、候補評価、天候順位、外観枠、診断を検索結果へまとめる。[detour-search/results.ts](../src/server/detour-search/results.ts)
- 検索結果、設定、経路取得済み候補の内部型を定義する。[detour-search/types.ts](../src/server/detour-search/types.ts)
- 寄り道なしの徒歩経路、到着見込み、残り時間を計算する。[direct-journey.ts](../src/server/direct-journey.ts)
- 経路・体験・待ち・余裕の秒数を合成し、到着期限との関係を計算する。[time-budget.ts](../src/server/time-budget.ts)
- 秒とタイムゾーンを含む日時を厳密に検査し、Unix時刻のミリ秒に変換する。[date-time.ts](../src/server/date-time.ts)
- 利用条件、営業、受付締切、時間予算を照合し、候補の可否と警告を組み立てる。[candidate-assessment.ts](../src/server/candidate-assessment.ts)
- 確認できた利用不可条件と、不明として候補に残す項目を分ける。[candidate-conditions.ts](../src/server/candidate-conditions.ts)
- 地点IDの包含関係をたどり、目的地そのもの、目的地の内部、共通の包含施設などを判定する。[place-relations.ts](../src/server/place-relations.ts)
- 候補の体験種別を選び、外観・屋内の利用条件の検査へ振り分ける。[candidate-access.ts](../src/server/candidate-access.ts)
- 利用条件の地点・目的地・体験の一致、出典、確認時刻、有効期間を検査する。[access-evidence.ts](../src/server/access-evidence.ts)
- 入場せずに外観を観察できるかを検査する。[exterior-access.ts](../src/server/exterior-access.ts)
- 屋内利用、予約、開始時刻、入場料、受付締切などを検査する。[interior-access.ts](../src/server/interior-access.ts)
- Placesの日付付き営業時間を日本時間の区間へ変換し、訪問全体が営業時間に収まるか判定する。[opening-hours.ts](../src/server/opening-hours.ts)
- カフェ・軽食・小規模展示の体験ID、体験時間と待ち時間の既定値を管理する。[experience-profiles.ts](../src/server/experience-profiles.ts)
- 対象と期間が合う体験時間の根拠を、登録値・公式・外部統計・推定の優先順で選ぶ。[duration-evidence.ts](../src/server/duration-evidence.ts)
- 外観観察を先頭の必須枠として、表示する最大3件の構成を決める。[experience-mix.ts](../src/server/experience-mix.ts)
- Google Weatherから候補の訪問時刻に対応する時間帯の予報を取得する。[weather.ts](../src/server/weather.ts)
- 候補の予報取得件数、同時実行数、処理時間を制限する。[visit-forecasts.ts](../src/server/visit-forecasts.ts)
- 天候を徒歩の寄り道向けの判断区分に変換する。[weather-policy.ts](../src/server/weather-policy.ts)
- 訪問時刻と予報の時間帯を照合し、天候による除外と優先順位の変更を適用する。[weather-selection.ts](../src/server/weather-selection.ts)
- 除外段階、理由、出典、判断値を公開用の診断にまとめる。[candidate-diagnostics.ts](../src/server/candidate-diagnostics.ts)

## 変更時に合わせて確認する箇所

- **入出力を変える**。APIの型、サーバーの入力検証、画面の応答検査、仕様書、対応するfixtureを照合する。[API入出力仕様](API入出力仕様.md)
- **候補の可否や時間を変える**。検索と選択後の再検証で判定が揃うか確認する。未確認の項目を暫定表示する場合は、警告コードと行程画面の表示も確認する。[候補の不明情報と除外理由](候補の不明情報と除外理由.md)
- **関数に説明を加える**。TypeScriptでは型に書かれている情報を使い、`@param`は秒とミリ秒、時刻の基準、同じ型の引数の役割などを補う。`@returns`は`null`や状態値の意味、`@throws`は呼び出し側が扱う例外を説明する。JavaScriptの`.mjs`では、同じ型の引数を取り違えやすい場合などに型付きの`@param`を使う。
