# 利用案内・プライバシーの設計

作成日・公式資料確認日：2026年11月9日。対象：ハッカソン公開版のよりみち。

## 位置情報の案内の先行実装

位置情報の案内を先に進める。`/about#privacy` に、現在地の取得タイミング、手動での出発地点指定、送信先と用途、GeminiのGoogleマップ連携での30日間保存を掲載する。入力画面では現在地取得ボタンの前に説明を置き、現在地を使う行程画面では再計算と直行への変更の前にも表示する。検索・候補・行程のフッターからも案内を開ける。

以下は利用規約・問い合わせ窓口を含めた全体の設計案。運営者名と窓口は確定後に掲載する。公開URLでの確認はデプロイ後に行う。

## 1. 今回作るもの

公開ページ `/about` を1枚作り、ページ内に「利用について（利用規約）」「情報の扱い（プライバシーポリシー）」「運営・お問い合わせ」をまとめる。ログインなしで直接開けるようにする。長い契約文や会員登録の仕組みは今回の対象にしない。

ユーザーは、ハッカソンに合わせた短い利用案内を希望した。Googleの資料は公開された利用規約・プライバシーポリシーを求めるが、別々のURLで2ページに分けるという要件は今回の確認資料では見当たらない。1ページ内に両方の見出し・本文・アンカーを用意する方式は、このプロジェクトの設計判断であり、Googleによる個別承認ではない。[Places APIの公式方針](https://developers.google.com/maps/documentation/places/web-service/policies)

## 2. 画面と導線

| 場所             | 表示・動作                                                                                                            |
| ---------------- | --------------------------------------------------------------------------------------------------------------------- |
| 共通フッター     | 「利用案内・プライバシー（別タブ）」から `/about` を開く。条件入力・候補・行程の各画面から利用できる                  |
| 出発地点の入力欄 | 現在地取得ボタンの説明を下記の短文へ更新し、`/about#privacy` へのリンクを添える。位置取得操作より前に読める状態にする |
| `/about` の先頭  | タイトル、最終更新日、利用について／情報の扱い／お問い合わせのページ内リンク                                          |
| 本文             | `#terms`、`#privacy`、`#contact` の順に通常の文章で表示。折り畳みの中に隠さない                                       |

現在の画面は検索条件・候補・訪問済み地点をReactの状態で保持しており、別ページへの移動で復元する仕組みはない。そのためフッターと説明欄のリンクは通常のa要素で `target="_blank" rel="noopener noreferrer"` を指定し、元のタブを維持する。リンク名に「別タブ」を含め、ページ内リンクは同じタブで移動する。`/about` からトップへ置くリンクは「よりみちを開く」とし、既存の行程を復元する「戻る」操作とは説明しない。

位置情報の説明文案：

> 現在地は、操作時に取得します。検索・再計算時に、出発地点・目的地・到着希望時刻などをサーバーとGoogleのサービスへ送り、寄り道の提案と経路計算に使います。位置情報を許可しなくても「場所を指定」で利用できます。詳しくは「情報の扱い（別タブ）」をご確認ください。

ブラウザの位置情報許可を維持し、同意済みとみなしてエージェント等が代行しない。既存のエラー表示を残し、取得ボタンの `aria-describedby` から説明文と該当エラーの両方を参照できるようにする。今回、新しい同意チェックボックス・同意記録DBは追加しない。これは画面を簡潔にする設計判断であり、あらゆる利用条件で追加同意が不要という結論ではない。

### 情報の扱い（プライバシーポリシー） `#privacy`

> 検索・再計算のために、入力した検索語、出発地点の座標、目的地、到着希望時刻、選択した体験や訪問済み地点のIDなどを扱います。現在地は操作時に取得し、移動を継続的に追跡しません。位置情報の許可はブラウザの設定で取り消せます。取り消した後は「場所を指定」で出発地点を変更してください。
>
> これらの情報は本サービスのサーバーで処理し、必要な情報をGoogleの場所検索・経路・天候・Geminiによる候補探索へ送ります。「Googleマップで徒歩ルートを開く」を押すと、出発地点・寄り道先・目的地がGoogleマップへ渡されます。
>
> 本アプリは検索や移動の履歴をデータベースに保存せず、現在の画面で使う情報をメモリ内に保持します。アプリ独自の広告・アクセス解析用Cookieや継続的な位置追跡は実装していません。ただし、外部サービスや基盤での処理・記録まで行われないという意味ではありません。
>
> 過剰なAPI利用を抑えるため、利用回数の制限用Cookieを使用します。有効期間は30日で、ランダムな識別子を保持します。検索語や位置情報はCookieに含めません。サーバー内では当日の操作別利用回数を管理します。
>
> Mapsを使ったGeminiの探索では、Googleの規定により、プロンプト・付随情報・生成結果が30日間保存され、サービスの信頼性確保等に使われます。Googleの他のサービスにおける取り扱いは、各サービスの規定をご確認ください。お問い合わせは下記の窓口へお願いします。

この節には、Googleプライバシーポリシーと[Maps groundingの保存に関する公式説明](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/zero-data-retention)をリンクする。30日間はMaps groundingに関する期間であり、Places・Routes・Weatherや基盤ログすべての統一保存期間として表示しない。

## 4. 実装と文面を照合するための記録

この表は設計者・実装者用で、掲載本文へすべて展開する必要はない。確認基点はmainのd293cc0。以下はコード・既存の公開作業記録による確認であり、今回ライブのクラウド設定や全ログを再監査した結果ではない。

| 処理           | 現在の扱い・確認箇所                                                                                                                                                                                                                        |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 場所検索       | 入力した検索語・地点IDをGoogle Placesへ送る。検索語は同一サイトのGETのURLにも入る。`src/lib/client/planner-api.ts`、`src/server/places.ts`、`src/server/place-details.ts`                                                                   |
| 候補探索       | 出発座標・目的地・到着希望日時・訪問済み地点ID、再検証時は選択地点・体験IDもGeminiへ送る。Maps探索と構造化抽出を使用。`src/server/grounded-detours/requests.ts`                                                                             |
| 経路・天候     | 経路の端点・徒歩指定をRoutesへ、訪問候補の座標をWeatherへ送る。`src/server/routes.ts`、`src/server/google-http.ts`                                                                                                                          |
| 外部地図       | クリック時にMaps URLsへ地点名・座標・地点IDを渡す。APIキー・候補トークン・到着期限・滞在時間・訪問履歴は渡さない。`src/lib/client/maps-directions.ts`                                                                                       |
| 画面内状態     | 現在地はgetCurrentPositionで取得し、watchPositionは使わない。検索条件・候補・訪問済み地点はReactの状態。DB・localStorage・sessionStorageへの履歴保存は実装していない。`src/components/trip-planner.tsx`                                     |
| サーバー・基盤 | 応答・外部取得はno-store。アプリに検索本文・位置・トークンを通常ログへ出す処理はない。既存Cloud RunのHTTPリクエストログ除外は作業記録に確認実績があるが、他のログや提供元の保存までゼロとはしない。[Cloud Run作業記録](CloudRun公開手順.md) |

「情報を一切取得・送信・保存しない」「完全に匿名」「すべて日本国内だけで処理する」とは書かない。HTTPログ除外とno-storeは、Google側の保存や全種類の基盤ログの停止を意味しない。今後、保存・分析・ログの追加をする場合は、実装に合わせて掲載文面も更新する。

本文を公開する前に、運営者の公開名と、実際に管理する問い合わせ先を確定する。基盤ログについて保存期間等を具体的に記載する場合は、対象ログと現行設定を確認してから書く。仮の名前・メールアドレスや、主催者への問い合わせ誘導を作らない。今回の設計作成は、この確認待ちで止める必要はない。

実装後は次を確認して記録する。いずれも現時点では未実施。

- 未認証で `/about` が200となり、利用規約・プライバシーポリシー・運営窓口・最終更新日を読める。
