# 2人開発の分担と開始手順

2026年11月7日作成。A・Bは役割名であり、人への割当はチームで決める。技術スタックは未確定。API仕様は「API入出力仕様.md」、画面開発用の架空データは[画面開発用の架空データ](../fixtures/search-success.json)を使う。

## 分担

| 役割          | 担当範囲                                                                             | 最初の完了条件                                                          |
| ------------- | ------------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| A：画面・体験 | 目的地指定、3入力、位置取得、候補カード、行程、エラー・不明表示                      | 仮データで入力→比較→選択→行程がスマホ画面で動く                         |
| B：API・公開  | 場所検索、Gemini、経路、天候、混雑情報の取得検証、体験時間の優先順位、期限判定、公開 | 新宿の実在候補を1件以上、実際の経路時間と出典付きで同じ応答形式にできる |

提出物：Aが動画・スライド、Bが説明書・著作物利用シートを取りまとめる。素材・API・ライブラリの出典と採用理由は使用者が記録する。現地検証・レビューは2人で行う。

## 最初に一緒に行うこと（60〜90分の目安）

1. GitHubの共通リポジトリと各自の作業コピーを用意する。現在のローカル文書が相手にも共有されていることを確認する。
2. Bを初期構成の担当とし、言語、フレームワーク、起動コマンド、公開先を決める。1つのWebアプリ内で画面とAPIを分ける構成を第一候補にする。
3. API仕様と仮データを2人で確認し、必要な修正を先に統合する。
4. 初期構成を統合した後、それぞれ別ブランチへ分かれる。Aは仮データ、Bは実APIで開発する。

## 編集範囲の境界

初期構成時に、以下に相当する実際のフォルダ名をREADMEに記録する。

- A：画面、見た目、ブラウザ側API呼び出し。
- B：サーバーAPI、外部サービス接続、時間計算、公開設定、任意の体験時間補正データ。
- Bが取りまとめる共有箇所：依存関係・ロックファイル、環境変数名、共通型、API仕様、ルート設定。Aが必要な変更はBへ伝えて調整する。
- [AGENTS.md](../AGENTS.md)・要件・PROJECT_MEMORY.mdを変更したら相手に共有する。役割外の変更が必要なら理由と影響を伝えてから進める。

## 統合ルール

- 各自のPC・別ブランチで作業する。完成単位でPull Requestを出し、相手が確認する。
- APIの項目名・単位・エラー形式を片側だけで変更しない。仕様と仮データを同時に更新する。
- 初日に仮データで接続確認し、日曜のうちに実APIで一連の操作をつなぐ。
- 共通ブランチを取り込んでから作業を再開し、統合後は入力から行程まで操作する。
- キーは各環境の秘密設定に置く。共有するのは変数名と取得手順だけ。実際のキーをGitHubやチャットへ貼らない。
- API設定・予算・公開先を管理するGoogle Cloudプロジェクトの担当はB。必要な権限を個別アカウントへ付与し、アカウントそのものを共有しない。

## それぞれのCodexに渡す作業指示

### A担当

リポジトリルートのAGENTS.mdと、docs/PROJECT_MEMORY.md、docs/よりみち要件定義書.md、docs/開発分担表.md、docs/API入出力仕様.mdを読んでください。画面側を担当し、fixturesの架空データで3入力→候補比較→行程を実装してください。不明・推定・デモの表示を保持し、天候・混雑はユーザーに質問しないでください。サーバー処理や共通設定は独断で変更せず、必要な変更を報告してください。完了時は変更ファイル、確認方法、残課題をまとめてください。

### B担当

同じ4文書を読み、サーバーAPI・外部接続・時間計算・公開を担当してください。API仕様に合わせ、新宿の候補を動的に取得してください。移動時間は経路API、体験時間は有効な登録値→外部根拠→推定の順とし、待ち時間を二重加算しないでください。位置・秘密情報をログに残さず、混雑・天候の欠損でも継続できるようにしてください。画面ファイルは担当外です。完了時は変更ファイル、接続・計算の確認結果、未対応事項をまとめてください。
